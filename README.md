# Изменения в форке mtslinker

Эта версия форка `Opragopa/mtslinker` содержит следующие изменения относительно оригинального `motattack/mtslinker`.

## Синхронизация видео и аудио

- Все видеофрагменты приводятся к `25 FPS`. Для лекций и демонстрации экрана это уменьшает объём обработки примерно на 17% по сравнению с 30 FPS.
- Все аудиофрагменты приводятся к `44100 Hz`.
- Финальный MP4 собирается с явным `25 FPS`.
- Пропуски видео заполняются чёрным кадром, а пропуски аудио — тишиной с частотой `44100 Hz`.
- Итоговый звук нормализуется фильтром:

  ```text
  loudnorm=I=-14:TP=-1.0:LRA=11
  ```

- По флагу `--multitrack` в итоговый MP4 записываются отдельные аудиодорожки:
  1. `Master` — микс всех найденных источников;
  2. `Лектор` — отдельный источник лектора, если MTS Link передал его идентификатор;
  3. остальные источники — отдельными дорожками (`Участник`, `Трансляция экрана` или `Аудио N`).

  Источники группируются по идентификатору потока из данных MTS Link, поэтому несколько фрагментов одного лектора попадают в одну дорожку. Если идентификаторов нет, каждый источник сохраняется отдельно.

Без `--multitrack` создаётся только дорожка `Master`, чтобы итоговый файл не разрастался без необходимости.

## Параллельное скачивание

Фрагменты записи скачиваются одновременно пулом потоков. По умолчанию используется 8 потоков:

```bash
mtslinker RECORD_URL --download-workers 8
```

Число потоков можно уменьшить для ограничения нагрузки или установить `1` для последовательного скачивания.

## Быстрая сборка

Финальная сборка выполняется через `ffmpeg`, без покадрового рендера MoviePy. Это ускоряет обработку длинных записей и сохраняет временные промежутки между фрагментами.

Во время сборки показывается единый progress bar от 0 до 100 процентов. Подробный поток логов ffmpeg скрыт.

Если ffmpeg не может обработать исходные файлы, автоматически используется fallback через MoviePy.

## Файлы записи и логи

- скачанные исходные фрагменты сохраняются в подпапке `fragments`;
- итоговый MP4 сохраняется в папке записи;
- полный лог обработки сохраняется рядом в файле `recording.log`;
- в терминале остаются только короткие сообщения о текущем этапе, скачивании фрагментов и завершении сборки.

## Аппаратное кодирование

При наличии поддержки в установленном ffmpeg форк автоматически выбирает:

- Apple VideoToolbox на macOS;
- `h264_nvenc` на компьютерах с NVIDIA RTX (быстрый пресет `p2`);
- `libx264`, если аппаратный кодировщик недоступен.

Битрейт видео подбирается по исходным фрагментам и ограничен диапазоном `900–6000 kbps`. Для типовых размеров используются минимальные значения около `1200 kbps` для 640×360 и `2500 kbps` для 1280×720, чтобы лекции не превращались в заметно размытое видео.

На Windows проверьте NVIDIA и ffmpeg так:

```powershell
nvidia-smi
ffmpeg -hide_banner -encoders | findstr /i "h264_nvenc hevc_nvenc"
ffmpeg -hide_banner -f lavfi -i color=c=black:s=128x128:r=30:d=1 -c:v h264_nvenc -f null NUL
```

Если третья команда завершается с кодом `0`, NVENC реально доступен. Сам `mtslinker` также выполняет короткую проверку и автоматически переключается на CPU, если кодировщик только заявлен в ffmpeg, но не работает с текущим драйвером.

## Локальная установка форка

```bash
git clone https://github.com/Opragopa/mtslinker.git
cd mtslinker
python3 -m pip install -e .
```

Запуск записи:

```bash
mtslinker "RECORD_URL"
```

Для закрытой записи добавьте `--session-id`. Отдельные дорожки спикеров включаются только явно:

```bash
mtslinker "RECORD_URL" --multitrack
```

На Windows после обновления клона из основной ветки:

```powershell
git pull --ff-only origin main
python -m pip install -e .
python -m mtslinker.cli "RECORD_URL"
```

Для обновления уже установленной editable-версии:

```bash
python3 -m pip install --no-deps -e /Users/opragopa/PROJECTS/MtsLinkerFork
```
